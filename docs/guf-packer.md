# GUF Packer

## Назначение

GUF Packer - браузерный инструмент для пакетной обработки файлов `.guf`. Он позволяет:

- загрузить один ZIP-архив с GUF-файлами или несколько отдельных `.guf` файлов;
- извлечь из исходных имён дату, время и очищенное имя;
- сформировать новые имена по шаблону;
- назначить общие и индивидуальные переменные;
- изменить порядок файлов drag-and-drop сортировкой;
- проверить результат перед экспортом;
- добавить описания файлов и общий текст README;
- скачать новый ZIP-архив с переименованными файлами.

Вся обработка выполняется в браузере. Исходные файлы не отправляются на backend.

## Где находится реализация

Основные точки кода:

- `src/pages/GufPackerPage.tsx` - композиция страницы и обработчики UI;
- `src/hooks/useAppState.ts` - состояние GUF Packer и операции над ним;
- `src/utils/zipHandler.ts` - чтение ZIP, создание `FileRow`, генерация результата;
- `src/utils/nameCleaner.ts` - разбор исходных имён;
- `src/utils/templateEngine.ts` - применение шаблонов и пересчёт имён;
- `src/utils/validation.ts` - проверки итоговых имён;
- `src/utils/persistence.ts` - сохранение состояния в IndexedDB;
- `src/components/FileUploader.tsx` - загрузка через input и локальный dropzone;
- `src/components/FileTable.tsx` - таблица, поиск и сортировка файлов;
- `src/components/TemplateEditor.tsx` и `src/components/MassActions.tsx` - шаблон и переменные;
- `src/components/ReadmeEditor.tsx` - общий текст README;
- `src/components/ValidationPanel.tsx` - отображение ошибок.

## Архитектура потока данных

```text
ZIP / .guf files
       |
       v
FileUploader / useGlobalFileDrop
       |
       v
useAppState
  |    |    |
  |    |    +--> validateFiles(files)
  |    +-------> recalculateAllNames(...)
  +-----------> IndexedDB persistence
       |
       v
FileTable + TemplateEditor + ReadmeEditor
       |
       v
     exportZip()
       |
       v
JSZip -> Blob -> file-saver -> download
```

`GufPackerPage` не содержит алгоритмов переименования. Он получает API хука `useAppState`, передаёт колбэки дочерним компонентам и показывает уведомления.

## Модель файла

Каждый файл представлен объектом `FileRow` из `src/types/index.ts`:

| Поле           | Назначение                                          |
| -------------- | --------------------------------------------------- |
| `id`           | UUID строки, создаётся через `crypto.randomUUID()`  |
| `order`        | Текущий порядок файла, начиная с `startNumber`      |
| `originalPath` | Исходный путь внутри ZIP или имя загруженного файла |
| `originalName` | Имя без директорий                                  |
| `extension`    | Расширение без точки, в нижнем регистре             |
| `file`         | Содержимое как `Blob` или `File`                    |
| `detectedDate` | Дата, извлечённая из имени                          |
| `detectedTime` | Время, извлечённое из имени                         |
| `cleanName`    | Очищенная часть имени                               |
| `variables`    | Значения переменных конкретного файла               |
| `newName`      | Рассчитанное итоговое имя                           |
| `description`  | Описание для README                                 |

Порядок в таблице является источником значения `{index}` и `{indexPad6}`. После перестановки файлов имена пересчитываются.

## Загрузка файлов

### ZIP

`extractZip()` в `src/utils/zipHandler.ts`:

1. открывает файл через `JSZip.loadAsync(file)`;
2. собирает только записи-файлы, пропуская директории;
3. сортирует записи по полному относительному пути через `localeCompare`;
4. по умолчанию оставляет только записи с расширением `.guf`;
5. получает содержимое каждой записи как `Blob`;
6. извлекает имя файла из пути;
7. создаёт `FileRow` для каждой записи.

Вложенные папки поддерживаются при чтении, но при экспорте структура директорий не сохраняется: файлы записываются в корень нового ZIP.

При загрузке ZIP к уже существующему списку добавляются новые строки. Имя архива автоматически становится `<имя исходного архива>_renamed.zip`, если пользователь ещё не менял имя по умолчанию.

### Отдельные `.guf`

`gufFilesToRows()` превращает выбранные браузером `File`-объекты в `FileRow`. Валидация загрузчика разрешает либо один ZIP, либо один или несколько `.guf`; смешивать эти типы нельзя.

Глобальный drag-and-drop перехватывается хуком `useGlobalFileDrop`, поэтому файлы можно бросить в любую область страницы GUF Packer. События внутренней сортировки таблицы при этом не используются для загрузки внешних файлов.

## Очистка исходного имени

`parseFileName()` последовательно выполняет следующие действия:

1. ищет дату в начале имени в формате `YYYY-MM-DD`;
2. ищет время в формате `HH-MM-SS`;
3. удаляет служебный префикс `ДО.` или `ПОСЛЕ.` без учёта регистра;
4. убирает начальные дефисы, подчёркивания и пробелы;
5. схлопывает повторяющиеся пробелы;
6. удаляет пробелы по краям.

Например:

```text
2026-04-17_16-16-17-ДО. Описание документа.guf
```

даёт примерно такие значения:

```text
detectedDate = "2026-04-17"
detectedTime = "16-16-17"
cleanName    = "Описание документа"
```

Расширение извлекается отдельно и добавляется к итоговому имени автоматически.

## Шаблоны

Текущий шаблон по умолчанию:

```text
{indexPad6}_{cleanName}
```

### Встроенные переменные

| Тег              | Значение                                                      |
| ---------------- | ------------------------------------------------------------- |
| `{index}`        | Порядковый номер без дополнения нулями                        |
| `{indexPad6}`    | Порядковый номер длиной минимум 6 символов, например `000001` |
| `{originalName}` | Исходное имя файла вместе с расширением                       |
| `{extension}`    | Расширение без точки                                          |
| `{date}`         | Найденная дата или пустая строка                              |
| `{time}`         | Найденное время или пустая строка                             |
| `{cleanName}`    | Очищенное имя без расширения                                  |

### Пользовательские переменные

Пользователь может добавить переменную, например `module`, и использовать её как `{module}`. Значения задаются массово в `MassActions` и затем применяются ко всем строкам.

У каждой строки также есть собственный `variables: Record<string, string>`. При пересчёте глобальные значения из списка переменных имеют приоритет над уже сохранёнными значениями строки.

### Алгоритм применения

`applyTemplate()`:

1. создаёт словарь встроенных тегов;
2. заменяет все вхождения встроенных тегов через `replaceAll`;
3. заменяет пользовательские теги из `row.variables`;
4. добавляет исходное расширение через `.extension`;
5. возвращает итоговую строку в `newName`.

Расширение не нужно добавлять в шаблон вручную. Например, шаблон `{index}_{cleanName}` даст имя `1_Описание.guf`.

`recalculateAllNames()` вызывается после загрузки, изменения шаблона, изменения стартового номера, переменных, имени файла и порядка строк.

## Изменение порядка

Таблица использует `@dnd-kit/core` и `@dnd-kit/sortable`:

- `PointerSensor` начинает перетаскивание после небольшого движения указателя;
- `KeyboardSensor` поддерживает сортировку с клавиатуры;
- после `onDragEnd` вычисляются индексы исходной и целевой строки;
- массив файлов перестраивается;
- порядок и все итоговые имена пересчитываются.

Поиск в таблице фильтрует отображение по исходному имени, очищенному имени, новому имени и расширению. Фильтрация не меняет фактический порядок массива.

## Валидация перед экспортом

`validateFiles()` проверяет каждую строку:

1. итоговое имя не должно быть пустым;
2. имя не должно содержать `\\ / : * ? " < > |`;
3. расширение исходного файла не должно быть потеряно;
4. итоговые имена не должны дублироваться без учёта регистра.

Кнопка экспорта блокируется при наличии ошибок. Дополнительно `useAppState` вычисляет `duplicateFileIds`, чтобы подсветить все строки с одинаковыми итоговыми именами.

Проверка дубликатов учитывает полное новое имя вместе с расширением. Две строки с именами, отличающимися только регистром, считаются конфликтом.

## README и описание файлов

Пользовательский текст из `ReadmeEditor` хранится в `readmeContent`.

Перед экспортом `useAppState` добавляет к нему автоматически сформированный раздел с описаниями строк, у которых заполнено поле `description`:

```text
--- Описание файлов ---
новое_имя.guf: Описание файла

<текст пользователя>
```

Фактически в архив добавляется файл `README.txt`. Это важно учитывать при документации и при дальнейшем выносе логики в отдельный пакет.

## Экспорт ZIP

`generateZip()` выполняет следующие действия:

1. создаёт экземпляр `JSZip`;
2. для каждого `FileRow` заново вычисляет имя через `applyTemplate()`;
3. добавляет исходный `Blob`/`File` под новым именем;
4. при наличии текста добавляет `README.txt`;
5. генерирует Blob с алгоритмом `DEFLATE`, уровень сжатия `6`;
6. передаёт Blob в `file-saver` и инициирует скачивание.

Экспорт выполняется в браузере и не требует сервера. Имя выходного архива берётся из `archiveName` и по умолчанию равно `renamed_files.zip`.

## Сохранение и восстановление

Состояние GUF Packer сохраняется в IndexedDB через `src/utils/persistence.ts`.

База данных:

- имя: `guf-renamer`;
- версия: `1`;
- object store `meta` - шаблон, порядок, настройки, переменные, README и метаданные файлов;
- object store `blobs` - бинарное содержимое каждого файла по его `id`.

Метаданные и Blob-ы хранятся раздельно. Автосохранение запускается с задержкой около 300 мс после изменения состояния.

При старте сначала показывается skeleton. Затем состояние загружается асинхронно. Если найден старый формат без `variables`, хук выполняет обратную совместимость для старых полей `prefix`, `module`, `code`, `docNumber`, `custom1` и `custom2`, а также старого `fieldValues`.

Шаблонные пресеты хранятся отдельно в `localStorage` под ключом `gd-helper-template-presets`.

## Управление состоянием

`useAppState()` предоставляет публичный API:

- загрузка: `loadZip`, `loadGufFiles`, `addFiles`;
- шаблон: `setTemplate`, `resetTemplate`;
- нумерация и переменные: `setStartNumber`, `setVariableValue`, `addVariable`, `removeVariable`;
- строки: `updateFileCleanName`, `updateFileDescription`, `reorderFiles`, `removeFile`, `removeFiles`;
- экспорт и очистка: `exportZip`, `clearFiles`;
- производные данные: `errors`, `hasErrors`, `errorFileIds`, `duplicateFileIds`;
- пресеты: `savePreset`, `deletePreset`, `loadPreset`.

Производные значения `errors`, `hasErrors`, множества идентификаторов ошибок и дубликатов вычисляются через `useMemo`.

## Ограничения текущей реализации

- Обработка выполняется в основном потоке браузера. Для очень больших архивов возможны задержки интерфейса; Web Worker пока не используется.
- ZIP сортируется по имени пути, а не по порядку записей внутри исходного архива.
- При экспорте вложенные директории не сохраняются.
- Входной ZIP фильтруется до `.guf`, но кнопка «Добавить» внутри таблицы передаёт выбранные файлы в общий `addFiles()` без отдельной фильтрации расширения.
- `README` экспортируется как `README.txt`, несмотря на пользовательское название README и комментарии в некоторых местах кода.
- IndexedDB содержит бинарные данные файлов и может занимать значительный объём диска.
- Сохранение не является облачным и не синхронизируется между браузерами или устройствами.

## Возможное выделение в `guf-core`

Для будущего Chrome Extension чистыми и переиспользуемыми кандидатами являются:

- типы входного файла и результата;
- `parseFileName`, `getExtension`, `getNameWithoutExtension`, `getBaseName`;
- `applyTemplate`, `recalculateAllNames`;
- `validateFiles`;
- функция построения ZIP, возвращающая `Blob` или `Uint8Array` вместо непосредственного вызова `saveAs`.

React-состояние, IndexedDB, уведомления, роутинг и DOM-скачивание следует оставить на уровне конкретного приложения. В текущем репозитории это разделение ещё не завершено: рабочая GUF-логика находится в `src/`, а `packages/guf-core` пока не оформлен как самостоятельный пакет.
